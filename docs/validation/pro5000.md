# Validation on `pro5000`

Date: 2026-11-20. Access: `ssh pro5000` (root inside a Docker container).

## Host

| Resource | Observed |
|---|---|
| OS / kernel | Alibaba Cloud Linux 3, `5.10.134-19.3.1.al8.x86_64` |
| CPU / RAM | 256 vCPU, ~1.5 TiB |
| GPUs | 8× NVIDIA RTX PRO 5000 72GB Blackwell, driver 580.159.03, CUDA 13.2 |
| Rust | 1.99.0 (installed already) |
| RDMA | no device exposed |

Installed for the verbs build:

```sh
dnf install -y libibverbs-devel librdmacm-devel pkgconf-pkg-config
```

This installed rdma-core 48.0 (`libibverbs 1.14.48.0`), but it does not create a
device in the container.

## Tests

```text
cargo test --workspace --locked        all workspace tests pass
cargo run -p plait-node -- devices     8 NVIDIA + CPU discovered
cargo run -p plait-node -- hetero      9 devices, 32 compute tasks
                                       placements {Nvidia: 29, Cpu: 3}
cargo run -p plait-node -- parallel    EP/DP/PP match references
cargo run -p plait-node -- rdma-selftest
                                       skipped: no verbs device
```

The discovery output includes:

```text
#0..#7  arch=nvidia  name=NVIDIA RTX PRO 5000 72GB Blackwell [12.0]
        memory_mib=73415  flops=395520000000  rdma=false
#4294967295 arch=cpu  name=cpu-256  memory_mib=1547159  rdma=false
```

`hetero` registers device profiles through `Command::RegisterDevice`, schedules
32 planned operations with `Mode::Compute` device keys, and verifies the same
placement on all three simulated replicas.

## Why RDMA did not run here

The `pro5000` session is a Docker container, not the host:

- `/sys/class/infiniband` is empty and `/dev/infiniband` does not exist;
- `lspci` shows only a Red Hat `virtio` NIC, no Mellanox/ConnectX/Broadcom RDMA
  function;
- `/lib/modules/$(uname -r)` is absent, so `rdma_rxe` cannot be loaded;
- the container lacks `CAP_NET_ADMIN` and `CAP_SYS_MODULE`;
- `modprobe rdma_rxe` reports `Module rdma_rxe not found`;
- `rdma link add rxe0 type rxe netdev eth0` reports `Operation not permitted`.

The real backend compiles and links (`plait-rdma` + `rdma-io 0.0.2`); the
two-QP self-test is skipped because no verbs device is visible. To validate it,
run on a host with an RNIC, or start the container with `--privileged` (or
`--cap-add=NET_ADMIN --cap-add=SYS_MODULE`) and the host `rdma_rxe` module
mounted, then run the Soft-RoCE setup in `docs/rdma.md`.

## What this validates

- heterogeneous device discovery and capability scheduling on real NVIDIA GPUs;
- replicated `DeviceProfile` and `Compute` placement through the EPaxos runtime;
- all EP/DP/PP/DSA reference runners on a remote machine;
- the RDMA build path against a different rdma-core version (48 vs 55).

It does **not** validate RDMA packet movement or vendor kernel execution.
